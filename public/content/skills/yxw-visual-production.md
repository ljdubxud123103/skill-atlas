# YXW 视觉生产

把剧本、分镜、参考图或已有提示词转换为可持续迭代、可检查并可直接执行的视觉资产或提示词。默认使用中文，尊重剧本事实、锁定资产和用户原话。

## 路由任务

先判断唯一主工作流；一次请求跨工作流时按依赖顺序串联，不混用模板。

- **资产生产**：人物、妆发服装、重点道具、无人场景定调、场景六视图、整剧资产规划。完整读取 [references/asset-production.md](references/asset-production.md)，再按对象读取其中指定的专项参考。
- **电影感静帧**：参考图分析、Seedream/GPT Image 类自然语言生图提示词、剧情代表性首帧。完整读取 [references/cinematic-still-prompts.md](references/cinematic-still-prompts.md)；若静帧调用已锁资产，同时读取 [references/asset-production.md](references/asset-production.md)。
- **Seedance 视频**：把剧情转换为视频提示词，或审核、重写已有视频提示词。完整读取 [references/seedance-video-prompts.md](references/seedance-video-prompts.md) 和 [references/video-prompt-review-loop.md](references/video-prompt-review-loop.md)。每次提示词生成或修订后自动执行审核 Loop，记录问题、完整修订版和最终通过结论；未经最终复检通过不得交付为可生成版本。
- **出图与记录**：用户明确要求直接生成、保存、登记或学习审美反馈时，完整读取 [references/operations-and-learning.md](references/operations-and-learning.md)。

只有用户、原稿或项目明确要求电影／导演／摄影师对标时，才在对应主工作流外完整读取 [references/film-reference-routing.md](references/film-reference-routing.md)。电影参考完全可选；使用时按本场剧情功能、空间、运动强度与情绪终点转译为可执行变量，不得把片名或上一场组合固定套用。

## 视频提示词强制审核门禁

把 [references/video-prompt-review-loop.md](references/video-prompt-review-loop.md) 作为视频提示词任务的唯一强制审核规范，执行下列不可跳过的门禁：

横向默认注意力预算为：导演意图／叙事17%、镜头／剪辑／节奏18%、空间／物理／动作17%、表演／情绪／台词16%、视觉媒介／光色／纵深10%、声音／节拍／声线9%、资产／参考一致性8%、模型能力／可行性／安全5%。按任务动态路由但总和保持100%；所有P0硬门禁独立保留否决效力。

1. 凡生成、审核、重写、续写、局部修改、单个 15 秒单元或整集批处理视频提示词，均在写作前完整读取本 Loop；用户无需再次要求“自检”。
2. 先锁定来源事实、每场唯一戏点与各单元阶段落点，再逐项完成九项导演控制：戏点／对比、空间拓扑、动作因果、镜头四通道、节奏／情绪路由、三种时序、动机化转场、声音骨架、参考职责；每镜先标记 `T 过场／P 叙事推进／E 情绪高潮／C 主角魅力`，无情绪过场默认压到 1—1.5 秒，E／C 主动放慢；同时保留原台词并设计可见表演，最后形成 `V0`。不得把 `V0`、局部补丁或未经复检的版本直接交付。
3. 从 `R1` 起逐项审核本 Loop 全部检查项，不得抽查、缩写、跳项或用通用自检替代。发现问题后生成累积保留既有要求的完整 `V1/V2/...`，并从第一项重新审核。
4. 每个 15 秒单元分别审核；整集或多单元任务在各单元通过后，再检查跨单元的动作、情绪、道具、台词、轴线、光线、场景切换和序号连续性。拆分单元沿用 `原序号A/B`，合并单元同时标注全部原序号。
5. 每轮均追加到 `video-prompt-review-log.md`，至少保留唯一 Review ID、镜头职能图、`V0`、逐项状态、问题清单、完整修订版和最终结论；即使首轮无问题也必须记录。
6. 只有九项导演控制的适用项全部落实、每镜 T/P/E/C 路由与时长一致、最终一轮所有项目均为“通过”或有明确依据的“不适用”，且硬性拦截清零、S 级重点明确、R 级冗余为零、连续性、站位收束和参考职责确认后，才可交付为“可直接生成版本”。
7. 如有无法安全推断的缺项，必须结论为“驳回修改”，列出最少待补信息；不得伪造通过。最终对用户仅展示最后一轮结论和通过版完整提示词，中间轮次默认留在日志中。

## 冲突优先级

按以下顺序裁决冲突：

1. 用户本轮明确指令与用户锁定的字段模板
2. 已锁定资产、真实参考图和已确认空间拓扑
3. 剧本事实、台词原文、时间线、身份、场合与物理连续性
4. 当前项目画风、市场红线、画幅与平台限制
5. 用户已验证的长期审美规则
6. 本轮新创意与通用电影美学

不得让长期偏好改写剧情事实，不得让电影感破坏资产可读性，不得让生成平台擅自重新设计锁定内容。

## 通用执行纪律

1. 仅在缺失信息会实质改变剧情、身份、锁定资产或空间拓扑时追问；否则作出明确、专业且可回溯的推断。
2. 保留用户提供的字段名、标点和顺序。用户无模板时才使用专项参考中的默认模板。
3. 最终提示词使用确定取值，不留“或”、斜杠选项、方向二选一或待用户补全变量。
4. 不伪造外部素材、资产 ID 或平台状态。缺少真实锚点时使用 `@[对象_待绑定]`，明确标注待绑定。
5. 用户只要求分析或提示词时停止在文本交付；只有明确要求出图时才调用图像生成或平台操作。
6. 出图前先完成确定性提示词；出图后保留原图、提示词、参考图、模型与版本之间的对应关系。
7. 任何密码、Cookie、令牌、验证码、Access Key、Secret Key 与支付信息都不得写入 Skill、项目库或反馈库。
8. 先按用户输入和目标识别真人实拍、手机纪实、2D、3D CG、白模、绿幕或混合媒介，不设置永久 `35mm Kodak Vision3 500T` 或其他通用介质基底。电影参考完全可选；只有用户、原稿或项目已提供时才保留，并转译为焦段、构图、光线、材质、运动、节奏与声音。
9. 上一镜头尾帧图默认只作为人物关系位参考：用于锁定人物左右、远近、座位、朝向、支撑关系和既有轴线。若新条需要承接尾帧中的人物姿态，必须同时更换摄影机位置与观察角度，以新的镜头重新拍摄；不得使用相同机位、相同角度复刻尾帧。尾帧为平视时，首镜改用俯视、仰视、过肩、主观视角或明显侧后方四分之三角度；尾帧为其他角度时同理选择不同视角。不得只靠轻微平移、推拉或裁切伪装成新镜头。新条首镜必须保持关系位与轴线连续，并从新的有效动作起幅。
10. 男主魅力先导片以“男主本人越帅越好”为最高目标，不以“画面帅、镜头帅”为目标。场景、构图、光线、道具和运镜只能托举男主的脸、眼神、姿态、动作与声线；凡摄影技巧抢过人物、低机位损害脸型、前景手部遮脸或场景奇观压过男主的方案，均按P0驳回。完整执行标准见 [references/seedance-video-prompts.md](references/seedance-video-prompts.md) 与 [references/video-prompt-review-loop.md](references/video-prompt-review-loop.md)。

## 完成前总检

- 输出是否走对工作流并使用对应模板
- 剧本事实、台词、锁定资产与空间关系是否未被改写
- 光线是否具有物理来源，材质、尺度、动作是否可信
- 所有视觉变量是否唯一确定，无术语堆砌或互相冲突
- 连续任务是否延续人物、服装、道具、场景状态、光色与空间坐标
- 电影参照是否与本场剧情和空间相符，是否已转译为可执行的构图、光线、色彩、运镜和节奏，而非只罗列片名
- 用户只要提示词时是否避免擅自出图
- 每次视频提示词是否已执行完整审核 Loop，所有硬性拦截清零，并把每轮问题与完整修订版追加到 `video-prompt-review-log.md`
